# 產業判定與版面

「這份財報寫在哪一套準則下」，以及那個答案決定了什麼。

跨 `core.industry`、`financialReports.summary`、`financialReports.statements`。

> 可信度：**程式碼 > 緊鄰常數的註解 > 這份文件**。

---

## 三份產業科目字典

科目工作簿是**三份產業各自的檔案**而不是一份統一方案，因為同一個代碼數字在不同產業會是不同科目——`58200` 在金融業是呆帳提存，在保險業則是保險專屬的成本列（拿不同期別、不同機構的真實財報確認過）。

- 金控業 = 母公司為金控的合併申報
- 金融業 = 銀行
- 保險業 = 人壽與產險

`data/` 在 repo 根目錄，也就是 `src/core/` 往上**三層**，不是兩層。這張表當初從 `src/acctfinder.py`（現在的 `financialReports/statements.py`）搬下來時兩層是對的，搬完之後每一個科目工作簿路徑都靜默指向 `src/data/`。沒有任何測試抓到，因為 summary 模式從來不載入工作簿，只有逐報表模式會。

## 產業怎麼判定

比對的是**申報主體自己的登記全名**（財報裡印的那個），不是產業字眼。單獨的「銀行」會誤判每一種機構都有的普通資產負債表科目（「銀行存款」「存放銀行同業」），所以這些關鍵字要求只有登記名稱裡才會出現的公司類型後綴。

檢查順序是保險業優先，因為金控自己的財報有時也會提到子行／子壽險的名字——**申報主體自己的後綴**該贏。人壽／產物保險的名字不會同時是金控或銀行的名字，所以實務上沒有順序衝突。

掃前幾個 `.md` 檔（依檔名排序）而不是只掃第一個：封面不一定帶登記全名。實測有一份財報的第 007 頁資產負債表沒有，但第 001 頁封面標題有。

`bank_candidates` 讀的是同一個「前五檔」視窗。只讀 `paths[0]` 曾造成一種情況：封面沒有銀行名的財報——正是 `detect_industry_category` 擴到五檔要解決的那一種——產業判得出來但銀行判不出來，然後 `cli` 把整個資料夾跳過。

## SUMMARY_LAYOUT 為什麼綁死產業

這份 layout 的代碼是**直接對文件生比對**的，summary 模式從不載入產業科目字典，所以代碼本身不帶產業資訊。**同一個數字在不同準則下是不同科目。**

把 layout 套到它不是為之而建的財報上**不會失敗**——它會把一個真實、解析正確的數字貼上錯誤的標籤。

國泰人壽的財報實測：產業正確判為保險業，然後「保險成本」被以標準化 term「呆帳提存(收回)」輸出，正負號還被 `apply_cost_sign` 翻了。`matched_label` 仍然是「保險成本」，但 `term` 才是 CSV/Excel 匯出與 `_MERGED_TERM_ORDER` 使用的欄位，而標準化 term 正是這份 layout 存在的目的。

**所以沒有 layout 的產業一律拒絕，不預設。**

金控業共用銀行的 layout：每機構覆寫表本來就是圍繞金控合併口徑建的（見 `SUMMARY_CODE_OVERRIDES_FINSUM` 關於 63000/64000 的說明），所以這些代碼已經在金控口徑的列上跑過。**沒有**獨立拿一份金控自己的財報重新驗證過——如果出現一份對不上的，給它自己的 layout，不要把這個清單放寬。

保險業刻意缺席。要給它 layout 得先有保險業方案自己的保費收入／保險給付等代碼，而這個 repo 裡沒有任何東西能建立那個對照；用猜的會產生上面那種錯貼標籤，而且更難發現。

## 科目字典工作簿怎麼讀

每張 sheet 裡有**兩組**代碼＋名稱區塊並排（修正前與修正後，IFRS17 前後的對照）。兩組都讀，衝突時修正後贏。

區分兩組的標題字樣**刻意排除任何可能同時是真實科目名的字**（「資產」「收益」是合法的一級科目名，不只是標題）。早期版本拿那些當標題提示，結果一列真實資料（代碼 10000 =「資產」）被誤判成標題列，資料起始列被推到它後面，那個代碼就靜默從字典裡消失了。

「修正說明」「備註」之後的欄位是解釋性文字，不是代碼／名稱資料。把它們算進區塊的欄位範圍，那些長文會透過「最長的非代碼文字就是名稱」這個啟發式被當成科目名，蓋掉真正短很多的名稱。

名稱欄用「最長非代碼文字」而不是固定欄位索引，因為至少在一份實際的 sheet 裡，名稱欄的位置會逐列漂移。

合併儲存格要先填平：openpyxl 對合併範圍只在左上角回傳值，其餘全是 None，而這些工作簿的標題大量使用跨欄合併。

## 權益變動表為什麼不支援

科目工作簿的第四張 sheet（權益變動表）是**轉置**的——代碼是欄標題而不是列首。這個工具的「一列一科目」比對處理不了。

它仍留在 argparse 的 `choices` 裡，這樣 `--help` 會列出它，而使用者拿到的是這個說明而不是「invalid choice」。它曾經一路走到 `load_code_dictionary` 然後以裸 ValueError traceback 收場，儘管 docstring 承諾會有清楚的錯誤訊息。

## 逐報表模式找不到區段標記時

`extract_statement` 在找不到報表區段標記（如「資產負債表」）時**掃整個檔案**而不是跳過。有些轉檔會把每張報表拆成獨立檔案，而不在資料頁上重複標題（北富銀真實財報確認：標題只出現在目錄）——要求標記會讓一整個資料夾的正確資料靜默產出零筆。

比對本來就是代碼精確相等，所以不限制區段不會像寬鬆文字搜尋那樣製造 false positive。
