# 法說會：詞彙比對與放款重組

簡報沒有科目代碼，所以**詞彙本身就是識別碼**。這是整個專案最寬的判斷面。

跨 `earningsCalls.terms`、`earningsCalls.matching`、`earningsCalls.summary`。

> 可信度：**程式碼 > 緊鄰常數的註解 > 這份文件**。

---

## 四個獨立的過濾器

`find_value_in_table` 上疊了四層過濾，每一層都是因為一個真實的錯數字才存在：

| 過濾器 | 擋掉什麼 |
|---|---|
| `entity_tier` | 金控母公司或兄弟子行的數字不是這家銀行的（富邦簡報實測產出過大陸子行人民幣表的存放比 72.17%） |
| `detect_unit_scale` | 同一個檔案裡不同表格混用百萬元與拾億元 |
| 占比／成長欄 | 「占比」欄不是餘額 |
| 百分比格 | `parse_numeric` 會剝掉 `%`，於是 `0.08%` 讀成 `0.08` |

第四個的具體後果：一份真實富邦簡報裡，`房貸` 因此命中了「業務別逾放比」表的房貸欄回報 0.08，`法說會放款餘額合計` 命中了比率列「逾期放款／總放款」回報 0.12。餘額型項目**永遠不可以**從百分比格取值。

`require_absolute` 在列方向那一側也要做同樣的欄位過濾：少了它，一個占比標籤的列（`外幣放款佔全行放款`）會在同分時贏過真正的絕對值列，然後那一列的每個期別又被百分比檢查全部濾掉，結果回 None，正確的那一列根本沒機會（國泰金簡報實測）。

## match_strength 的三層

- **3** = 精確別名命中（整段 strip 後與別名完全相等）
- **2** = 子字串別名命中
- **1** = composite（加權子詞分數過門檻）
- **0** = 沒命中，或被 negative term 否決

精確勝過子字串勝過 composite。理由：像「淨收益」這種總額層級的通用詞，是很多不相關複合科目名的字面子字串（手續費淨收益合計、利息淨收益…），接受在資料夾裡任何地方找到的第一個子字串命中，會靜默抓到錯的一列。

所以 `find_term_value` 找的是**整個資料夾裡最強的那個命中**，不是第一個。一個通用詞可以在多個機構的表裡都精確或子字串命中（`營業費用` 同名地出現在子行自己的數字與金控母公司的合併數字裡），先找到的不一定是對的。只有在找到同機構層級的精確命中（rank `(3, 1)`——沒有東西能贏過它）時才提早停止。

## 空白別名為什麼是信任邊界

`TermSpec` 是這個套件的信任邊界：它拒絕一份會匹配所有東西的設定，而不是讓它通過去產生有自信的錯數字。

空字串是**每一個**字串的子字串，所以一筆空白別名會讓那個詞在整個資料夾裡以強度 2 命中**每一列**，壓過任何 composite。空白的 negative term 則反過來否決所有東西。

`Component(**c)` 自己丟的裸 `TypeError` 既沒說檔案、也沒說是哪個詞、也沒說哪個欄位——在一份四百個詞的設定檔裡沒東西可搜。所以 `from_dict` 把缺漏／多餘欄位講清楚，`load_terms` 再包上檔名與詞名。

## 標題也要套 negative_terms

一個詞的 `negative_terms` 會否決它自己的列／欄標籤，**投影片標題也要套同一組**，因為標題就是標籤的上下文。

真實富邦簡報：一個標題平平寫著「存放比」的欄位，坐在「外幣放款及債券投資佔外幣存款比例」這張投影片底下——那是只算外幣的比率，光看欄標籤沒有任何辦法跟這個詞要的整體存放比分開。

列方向那一側對應的是 `_row_sections`：把每一列對應到最近的「裸列」（第一格有字、其餘全空），也就是 `台幣`／`外幣`／`整體` 這種行內小節標題（中信金簡報確認：`放款利率`／`存款利率` 每個幣別區段各重複一次，列標籤自己完全沒有幣別字樣）。這讓 negative_terms 能靠**所在區段**否決候選，即使列標籤本身沒有東西可否決。

## 用標題當退路時的唯一欄規則

表格自己的列／欄標籤太通用（`放款餘額`／`占全行放款`），但那個詞其實是表格上方的區段標題（`## 外幣放款`）——真實簡報確認過的模式。

這條退路**只在剩下恰好一個候選值欄／列時**才安全。理由與更多案例寫在 [判不出來就拒絕](na-and-refusal.md#判不出來就拒絕在這個-codebase-的實作)。

`_heading_topic` 會剝掉標題開頭的 `公司名－` 前綴（`國泰世華銀行－外幣放款` → `外幣放款`），這樣比對不會被永遠存在的公司名干擾。但**機構偵測要用未剝的 `heading_raw`**——剝掉的正好就是它需要的那個公司名前綴。

## find_term_value 的回傳順序陷阱

`find_term_value` 回傳 `(matched_label, value, source_file, period_label, is_percent, unit_scale)`。
它包的 `find_value_in_table` 回傳 `(value, matched_label, period_label, strength, entity, is_percent)`。

**前兩個是相反的。** 兩個都是 6-tuple，兩個都被位置解構使用。`tests/test_l2_lookup.py` 把這兩個順序並排釘住了。不要為了「一致性」去改其中一個而不改每一個呼叫端。

`unit_scale` 是隨值帶著走而不是就地套用的：比率項目（無單位）與 CIR 的輸入（兩個數字相除，共同單位會抵消）可以忽略它，餘額項目才用它正規化。

## 放款重組：每家的公式

每家簡報拆放款的方式都不同，而且沒有一家符合這個專案要的形狀（企業／房貸／個人／信用卡循環四個互斥桶，加總等於總額）。原始命中的值必須先做每機構算術，跨機構才是同一個意思。

**北富銀**：印出來的 `個人放款` **綁了** 房貸 + 信貸 + 其他 + 信用卡循環，所以房貸與信用卡循環要拉回來，剩下信貸 + 其他。`企業授信` 不含政府放款，而政府放款在這裡屬於企業桶。
驗證：1172.2 + 154.0 + 1209.0 + 11.5 = 2546.7，對上簡報自己的授信餘額合計 2546.6（四捨五入）。

**中信**：數字是集團口徑、含海外子行，本專案不納入；印出來的 `企業放款` 只有台幣，所以外幣放款要加回來。`信用貸款與其他` 裡仍然含信用卡循環，而簡報從不單獨拆出來（所以要走下面的金管會退路）。
驗證：1699 + 1393 + 299.1 + 17.9 = 3409.0 = 簡報的總放款 4246 − 海外子行 837。

中信的外幣放款是從簡報自己的「外幣放款成長率-依分子行」分解**加法**建的，而不是 (總外幣放款 − 海外子行)：減法形式在 Q4 2025 給出 670，加法形式給 682，因為那個分解的三列加起來並不精確等於頭條總額。加法形式才符合預期的口徑（境內＋境外分行，不含海外子行）。

**玉山**：印出來的 `房貸` 只涵蓋房屋貸款；`個人擔保貸款`（依簡報自己的註腳是全額擔保的個人放款）在這裡是同一個經濟桶。印出來的 `個人放款` 綁了三個個人類別，所以無擔保那塊只有 `小額信貸`。總額是四個重組桶相加，不含海外子行——與中信的處理一致。

**國泰**：不動。它的簡報本來就公布四個互斥的桶，而且加總精確等於它自己講的放款總額（942.6 + 1404.9 + 477.7 + 22.2 = 2847.4）。只有信用卡循環要從金管會資料集補，因為它報的是 `信用卡放款`。

**每個公式讀的都是 RAW（重組前）的值字典**，所以公式之間看不到彼此的輸出，寫的順序無所謂。

重組後文件自己的列標籤已經不描述那個數字了，所以 `matched_label` 改成顯示公式本身，讓數字仍然可以追回它的輸入。

## 放款重組的容忍度是怎麼來的

四個重組桶應該加總等於重組後的總額。四家 Q4 2025 真實簡報驗證：中信與玉山對到分，北富銀差 0.1、國泰差 0.03，純粹是簡報自己一位小數的進位。

`_LOAN_RECONCILE_TOLERANCE = 2.5` **是照簡報自己的進位開的，不是照算術誤差**：中信的個體放款表印的是整數拾億元，四個組成加一個總額最多累積約 ±2.5 的進位；而且那份簡報**自己的列本來就對不起來**（組成加總 4,044，印出來的總放款 4,043）。門檻設得比這低，會在來源自己的進位上觸發，而不是在擷取器做錯什麼的時候。

超出容忍度時是寫進 `note` 而不是靜默接受——同一個原則見財報側的資產＝負債＋權益檢查。

## 為什麼不併進 BANK_PROFILES

`LOAN_RECOMPOSITION` **刻意不**跟其他每機構表一起併進 `BANK_PROFILES`。兩個理由：

它是**邏輯不是資料**——巢狀在 dict 字面量裡的 lambda，正是靜態 import 檢查看不見的那個構造（所以 `tools/undefined.py` 要走進 dict 裡，L2 測試套件要把九個都執行過）。搬它帶的風險跟其他表不同。

而且它自己會安全退化：這裡沒有條目的機構就是不做重組，那是正確的預設（國泰本來就沒有），而缺一筆 `composites` 或 `aliases` 產生的是錯的或缺的數字。所以 profile 完整性檢查對它沒有東西可以強制。

## 信用卡循環的金管會退路

好幾家簡報從不單獨公布信用卡循環（中信折進信用貸款與其他，國泰只報總計的信用卡放款），但中信的個人放款公式要減掉它。

金管會資料集每月對每一家都公布，所以在——而且只在——簡報自己沒提供時從那裡補，並把千元換算成放款表用的十億元。

逾放比率／備抵呆帳/逾期放款來自**另一張**金管會表（`fetch_overdue_loans`，全行 NPL 揭露，不是信用卡那張），完全沒有法說會來源。兩者在機構已知時各抓一次（不是只在信用卡循環缺的時候）。
