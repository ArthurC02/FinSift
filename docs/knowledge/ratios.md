# 比率：來源、年化、交叉核對

同一個東西有兩個獨立的量測，而且哪一個都不許靜默蓋掉另一個。

跨 `financialReports.ratios`、`financialReports.profitability`、`financialReports.summary`、`earningsCalls.summary`。

> 可信度：**程式碼 > 緊鄰常數的註解 > 這份文件**。

---

## ROA/ROE 的三個來源

優先順序固定：

1. **財報自己揭露的獲利能力表**——**照揭露值使用，不再年化**。早期版本一律用 `x4/季數` 縮放，假設台灣的銀行一致地在這裡報未年化的累計數。三家銀行各兩期的交叉比對推翻了這個假設：中信與玉山的 Q1 揭露值跟自己的 Q4 大致同量級（已年化），國泰的 Q1 大約是 Q4 的四分之一（確實未年化）——**慣例並不一致**，盲目縮放對其中一部分必然是錯的。
2. **法說會簡報自己報的數字**——由呼叫端（`userInteractions.cli`）提供，不是在這裡查，因為財報側不能 import 法說會側（會循環：法說會側已經 import 了 `financialReports` 的 entities／ratios／statements）。
3. **本財報的手算公式**（`compute_ratios`），明確標示為近似值。

不論哪個來源勝出，手算公式**都會**另外算一次當交叉核對值，**永遠不用它靜默覆蓋**揭露值；兩者背離超過門檻時在 `note` 說明。那個差距本身就是有用的訊號，不是該藏起來的東西。

三個來源全空才回 None，而那一列的 note 會把三個都點名——那才是告訴讀者該去找獲利能力表、還是去找手算公式缺的那幾個資產負債表代碼的資訊。

## 獲利能力表有三種版面

`profitability.py` 只做「讀」，不算任何比率。三種版面都在真實財報裡見過：

**Layout 1 — 列＝機構，欄＝項目**（國泰真實 `.md` 資料驗證，標題是表格上方的散文而不是真正的標題列）：

```
| 合併獲利能力 | 0.27 | 0.22 | 5.13 | 4.23 | 43.64 |
| 本 公 司 | 3.25 | 3.29 | 4.20 | 4.25 | 98.29 |
```

欄序由法定揭露格式固定：ROA稅前、ROA稅後、ROE稅前、ROE稅後、純益率。期別是**區塊層級**的區分（一個期別一張表，由一行民國日期**區間**散文帶出）。`合併獲利能力` 那一列即使在下方子公司列被雜散的括號／pipe 破壞時也一定是乾淨的 pipe 分隔，所以機構列用續行折疊重建（跟科目代碼列同一招），值靠掃 token 取，不信任固定格數。

只有**稅後**會出現在輸出裡；稅前在內部解析是為了保住欄位位置。裸 `-` 佔位符也要消耗一個位置，這樣某個項目缺席時固定欄序仍然成立——全形破折號（`—`）曾經匹配不到任何東西，於是它不佔位，那一列後面每個項目都被讀早一欄。

**Layout 2 — 列＝項目，欄＝期別**，一機構一張小表，由編號標題行（`1. 玉山金控及子公司`）帶出。這條路徑是從那份財報的原始 PDF 文字（pypdf）建的，**還沒**對過這個版面的真實 `.md` 轉檔輸出——視為暫定，等真實轉檔驗證。

**Layout 3 — 列＝項目，欄＝期別，單一機構**（沒有編號標題）。這是目前見過的每一份真實**個體**財報自己的附註揭露實際採用的形狀（中信／國泰／玉山確認）。這裡只有一個機構——這份財報自己的銀行——所以每一列都歸給它（`entity: None`；呼叫端本來就知道這個資料夾屬於哪一家）。

Layout 2 已經認領的表 Layout 3 會跳過，避免同一張表被算兩次。這個防護只收窄 layout 3 這一邊，不動 layout 2 自己的歸屬：兩邊若對某個標題判斷不一致，同一張表會被抽出兩次、數字相同，一次掛標題文字一次 `entity=None`，而 `_select_profitability_entry` 偏好 `entity=None` 那份（它永遠在範圍內），所以最壞情況是多一筆冗餘，不會少一筆。

## 期別標題有四種寫法

`parse_period_header_date` 把獲利能力表的欄標題解析成 `(年, 月, 日)` 排序鍵，四種格式都是真實財報確認過的：單一民國年月日（`114年12月31日`）、點分隔（`114.12.31`，中信）、期間**區間**（`115年1月1日至3月31日`，國泰）、裸會計年度（`114年度`，國泰／北富銀——一律當全年，鍵成年末 `(年,12,31)`）。

**區間必須在單一日期之前檢查。** `_SINGLE_DATE_RE` 是不錨定的 `.search()`，碰到 `115年1月1日至3月31日` 會誤中裡面嵌的**起始**日期，把期別標成它的第一天而不是正確的季末（國泰／北富銀 Q1 財報實測：值還是對的，因為當期與去年同期兩欄得到一致的錯誤處理，但顯示的期別標籤是錯的）。

Layout 3 早就用了認得區間的解析器；Layout 2 的擷取器一直沒拿到同一個修正。

## 手算公式為什麼要先除以季數

`net_income` 是**年初至今的累計數**，不是單季數——直接從財報自己的損益表欄位標題確認：Q4／年報的欄位寫「114年度金額」（**全年**），Q2 的欄位寫「一月一日至六月三十日」（上半年**累計**，不是單獨的 Q2）。

早期版本假設相反（單季），然後一律 `x4`。對 Q4 財報（本來就是全年）這會把已經年化的數字再乘四倍——三家銀行的 Q4 交叉核對出現約 4 倍偏高，就是這個原因。先除以季數在 `quarter_num=4` 時正確地退化成無操作，其他季則把部分年度的累計數投射成全年。

平均餘額為零要當成一般查詢失敗丟 `RuntimeError`：`ZeroDivisionError` **不是** RuntimeError 的子類別，讓除法自己爆會拖垮整次執行而不是退化。

`compute_ratios` 走的是 `find_code_value`（無區段限制）而不是早期那個以區段標記限制的查詢。後者實務上不可靠：一份真實國泰財報的損益表頁面從不重複自己的「…綜合損益表」區段標題，於是標記搜尋靜默找不到東西，儘管代碼列就在那裡。它當時用的代碼（19999/39999/69000）也是本專案改用產業科目字典之前留下的，確認在現行三本工作簿裡完全不存在。

## 合理範圍為什麼開得那麼寬

`_ROA_PLAUSIBLE` = [-5, 5]%、`_ROE_PLAUSIBLE` = [-50, 50]%。基礎是四家目前支援的銀行本季實際觀測：ROA(稅後) 落在 0.24%–1.12%，ROE(稅後) 落在 3.33%–15.02%。

**刻意寬**：虧損季是完全正常的輸入。所以這個檢查在真實資料上幾乎不該觸發——真的觸發了，那非常可能是解析錯誤（代碼錯、期別欄位錯、% 號誤讀），而不是某家銀行真的是離群值。

它跟交叉核對背離是**兩個獨立的訊號**：那個標的是兩個量測之間不一致，這個標的是不管來源、不管一不一致，數值本身就不合理。兩個都觸發時兩個 note 都留，不互相覆蓋。

## 交叉核對為什麼比較量級

背離檢查比較的是**量級**，而且正負號相反直接判定背離。

分子原本是 `max(value, crosscheck)` 且沒有 `abs()`，於是虧損季可能算出 1.0 甚至負的比值而靜默通過：`max(-3.0, 1.0)` 是 1.0，`max(-3.0, -1.0)` 是 -1.0。正負號相反代表一邊說賺一邊說賠，那是最大的分歧，卻從來沒被報出來過。

背離的 note **不斷言原因**：手算公式自己那套假設對 Q4／年報財報本來就沒驗證過，所以這裡的差距不是「揭露值有錯」的可靠證據。措辭要停在「值得再看一眼」。

## CIR 為什麼從法說會搬到財報

CIR 現在是 `abs(營業費用) / 淨收益`，直接取**同一份財報**的兩個數字，不做交叉核對。

它以前算在法說會側，用簡報自己的營業費用／營業收入表。但那個口徑跟財報個體的 58400/4xxxx 不同——中信 4Q25 簡報那一頁的營收／費用跟財報個體數字差了大約一個數量級，不是四捨五入層級的差距。同名之下比的是兩個真正不同的量。

## 法說會的比率為什麼不年化

早期版本會把法說會的比率項目也乘 `x4/季數`，假設簡報表格的比率跟財報損益數字一樣是年初至今的累計流量。

真實簡報（中信金 2Q25/1Q26、國泰金 2Q25）對這裡每一個比率項目都推翻了那個假設：NIM、存放比、放款均率、存款均率，以及當時算的 CIR，全都已經是年化率或時點比率——比對同一份簡報的 1Q/1H/9M/FY 欄可以確認，它們維持在同一個量級而不隨期間長度縮放。

於是 `x4/季數` 產生了不對應任何東西的不可能值（>100% 的存放比、>100% 的成本收入比）。已移除；只顯示如揭露值，跟餘額類項目一樣。
