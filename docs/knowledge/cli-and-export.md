# 資料夾分類與匯出

`src/userInteractions/cli.py`：判斷資料夾是財報還是法說會，跑對應的擷取器，把結果合成一份輸出。

> 可信度：**程式碼 > 緊鄰常數的註解 > 這份文件**。

---

## 資料夾怎麼分類

兩種訊號：

- **財報訊號**：表格列的第一格是三本產業科目字典（金控業／金融業／保險業）任一裡的精確代碼。這是**權威的**——只有真正的編碼財報有這些。
- **法說會訊號**：`法說會`、`法人說明會`、`說明會`、`投資人簡報`、`法人電話會議` 等封面字樣出現在任一檔案裡。

**兩種訊號同時出現時代碼列贏**，因為那是結構證據而不是文字提及。法說會簡報有時會把同樣的區段**名稱**（如「資產負債表」）當成摘要表裡的一個純列**標籤**，純文字標記搜尋會在那裡誤判。

`load_all_codes` 取的是三本字典 × 三張報表的代碼**聯集**，只用來認「這一列的行首格是**某個**真代碼」，不用來解析特定產業的字典——那件事晚一點才做，等資料夾已經被認定是財報之後。

用 `rglob` 而不是 `glob`，跟 `detect_bank`／`find_code_value`／`collect_statement_rows`／`find_term_value` 一致。用 `glob` 時，`.md` 檔放在子目錄的資料夾會被分類成 None 而跳過，但直接對同一個資料夾跑逐報表模式卻正常。

## 簡式揭露怎麼認

`活期性存款比率` 是季度**簡式**財報網站揭露（依「公開發行銀行財務報告編製準則」第三十二條）的特徵列——這一行比率不屬於完整個體財報那 150–280 個檔案圍繞的三大報表任何一張，而且在中信／北富銀／國泰三家的真實 114Q4 簡式揭露裡都確認存在。

再配一個**低檔案數上限**（完整財報 150–280 檔，簡式約 10–15 檔，門檻設 30），這樣一份剛好在某處也揭露了這個比率的完整財報仍然分類成 `fin_report` 而不是 `fin_report_summary`。

## 合併輸出的列順序

一個財報資料夾與一個法說會資料夾 1:1 配對時，兩邊的列合併成**一張** sheet 而不是兩張，順序由 `_MERGED_TERM_ORDER` 固定。

它**刻意完整寫出**（而不是「先財報詞再剩下的法說會詞」），這樣這份清單就是合併表列序的唯一真相來源。`merge_fin_and_con_rows` 只有在遇到完全沒列在這裡的詞時才退回來源順序（將來新增的 `SUMMARY_LAYOUT`／法說會項目）。

財報側先檢查，因為活存比與 CIR 只住在那邊。同名的法說會列是**被取代**而不是還在待處理——少了這一步它會落到尾端的 extend，那個詞就被輸出第二次，跟這個函式自己承諾的「每個詞恰好出現一次」矛盾。

## 財報與法說會怎麼配對

**先把所有資料夾分類完**（在跑任何擷取之前），這樣財報資料夾才能跟它自己的法說會兄弟配對。這只有 ROA/ROE 的法說會退路需要（見 [ROA/ROE 的三個來源](ratios.md#roaroe-的三個來源)）。

恰好各一個時配對是明確的。任一邊是 0 個或 2 個以上就沒有可靠的配法，ROA/ROE 直接落到它其他的來源。

`lookup_concall_roa_roe` 住在這裡而不是 `financialReports` 裡面，因為只有這個模組同時 import 兩個套件；`financialReports` 去 import `earningsCalls` 會是循環（法說會側已經 import 了財報側的 entities／ratios／statements）。

配對成立但**一邊沒產出列**時（例如銀行判不出來，`run_fin_report` 回 None），另一邊被扣住準備合併的那份仍然要以自己的 sheet 進到活頁簿。少了這一步它會被靜默丟掉，使用者拿到一個整個資料夾都不見的 Excel，而輸出裡沒有任何一句話說明。

同一個資料夾被選兩次（在對話框裡很容易發生）會去重，保留先出現的順序，否則同一次擷取會跑兩遍也匯出兩遍。

## Excel 的百分比與千分之一

**百分比：** Excel 原生的百分比型態顯示時會把儲存值乘以 100（底層值是分數，`0.654` 顯示成 "65.40%"）。但這個 codebase 裡每一個比率值本來就已經**存成百分比數字**（65.4 就是 65.4%，見全域的 `format_pct`）。

所以除以 100 **只在這裡**做，在寫入 Excel 原生百分比格的那一刻，其他任何地方都不做——內部「已經乘過 100」的慣例完全不動。

**千分之一：** 資產負債表／損益表金額在每一份來源文件裡都是新台幣**千元**。除以 1000（→ 百萬元）**在匯出邊界**做，這樣內部值在其他所有地方（自我檢查、印出的摘要、CSV 匯出）都保持文件自己用的單位。比率（`is_percent`）不是金額，不動。

因為有那個除法，被縮放過的儲存格一律顯示到小數三位，避免千元以下的精度被靜默捨掉。

寫進去的是**真正的數值加上 Excel 數字格式**，不是預先做好的顯示字串——這樣值在公式與排序裡還能用。

## 匯出檔為什麼在 Downloads

一份合併檔（每個資料夾一張 sheet），存到 Downloads，不放進任何來源資料夾，也不放它們的共同上層（那不一定是 Downloads），然後立刻開啟，這樣執行結果不用去找。

`PermissionError` 代表前一次的匯出還開在 Excel 裡（自動開啟會鎖住檔案直到關閉）——退回一個帶時間戳的檔名，而不是讓整次執行崩掉。

資料夾選取對話框預設開在 Downloads：Windows 原生對話框否則會記得**某個其他不相關程式**上次用它時的目錄（例如某個舊專案的資料夾），而不是這些 `.md` 轉檔實際住的地方。

## 子命令為什麼用 peek argv 而不是 subparsers

`cli` 自己的 CLI 吃裸的位置參數（`cli <folder> <folder>`），在它外面加 subparsers 會改掉大家已經在用的介面。

子命令名稱永遠不會是資料夾名稱，所以偷看 `argv[1]` 是明確的；其他任何東西原封不動落到下面的 parser。三個被路由的套件各自保留自己的 `argparse main()` 完全不變，所以它們已經文件化的每一個旗標都還能用，一個都不用改。

`python src/userInteractions/cli.py` 會把**這個目錄**放進 `sys.path` 而不是 `src/`，兄弟套件因此解析不到。這是唯一一個使用者被告知要用路徑執行的檔案（它是單一 CLI），所以它自己 bootstrap `src/`，而不是要求每個人設 `PYTHONPATH`。

`data/` 與 `npl_cache/` 在 repo 根目錄，也就是 `src/<套件>/` 往上**三層**，不是兩層。這件事在這個 repo 咬過四次（`core/industry.py`、`earningsCalls/summary.py` 的 `--config` 預設、`regulatorDatasets/disclosures.py` 的快取目錄、以及這裡）。
