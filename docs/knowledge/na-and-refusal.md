# N/A 與拒絕

這個 codebase 反覆出現的失效不是崩潰，是**靜默的錯數字**。所以「判不出來就拒絕」是紅線，而 N/A 必須說得出自己是哪一種 N/A。

跨 `financialReports.summary`、`earningsCalls.summary`、`financialReports.entities`。

> 可信度：**程式碼 > 緊鄰常數的註解 > 這份文件**。

---

## N/A 的六種成因

N/A 不是一種狀況。每一種的修法不同，所以每一列 N/A 都在 `note` 裡標明是哪一種（同一個字串也會在 `-v` 印到主控台）。

| note 開頭 | 意思 | 修法 |
|---|---|---|
| `code XXXXX (X) not found in any file` | 這家用了別的代碼 | 確認財報裡真的沒有，再加 `code_overrides` |
| `'X' - none of [...] found in any file` | 標籤比對沒命中 | 加別名到該項的 `label_aliases` |
| `'X' has no formula defined for bank 'Y'` | 這家沒有該 composite 的公式 | 逆推組成代碼後補進 `composites` |
| `'X': component code Z not found` | composite 缺一個零件 | 同第一列 |
| `CIR needs 淨收益 and 營業費用...` | 上游兩列自己就是 N/A | 先修上游 |
| `no ROA/ROE: filing discloses no 獲利能力...` | 三個來源全空 | 見 [ROA/ROE 的三個來源](ratios.md#roaroe-的三個來源) |

**`note` 是唯一會進到匯出檔的那份副本。** 主控台的 `-v` 輸出在 `--export csv`／`--export excel` 路徑上根本不會印。在匯出檔裡，「這家沒揭露」跟「我們讀錯了這份財報」長得一模一樣——那正是差別最要緊的地方。

法說會側同一個原則：金管會來源的那幾列（逾放比率、備抵呆帳/逾期放款、以及簡報自己沒揭露時的信用卡循環）在拿不到值時，`note` 寫的是**哪一種**拿不到——「這家從來沒對照過金管會名稱」跟「資料集連不上」是兩個問題（見 [金管會名稱對照](entity-resolution.md#金管會名稱對照為什麼只有四家)）。

## 活存比為什麼永遠是 N/A

**而且那是正確結果。** 十家的財報裡只有「活期存款」的餘額列，沒有任何揭露的比率。按紅線第五條，不代算。

`活期性存款比率` 是季度簡式揭露裡確認過的真實措辭。其他幾個別名是更早的猜測寫法，留著以防完整年報／季報用不同的措辭講同一個比率。

這一列是 `kind: "label"`——它沒有科目代碼（是揭露的比率，不是被編碼的資產負債表／損益表科目），純靠標籤文字比對，不走 `build_code_index` 的代碼批次通道。

## 整份讀錯的警告

每一列 N/A 自己帶原因，但那是**逐列**的：它說的是這一行為什麼缺，不是整次執行走偏了。

版面整份被誤讀的財報，產出的形狀跟成功的一模一樣，而 csv／excel 路徑從來不印列出來給人看。所以另外有一個 `summary_coverage_warning`：超過一半的列是 N/A 就警告。

門檻**刻意寬鬆**：少數幾列 N/A 是常態（活存比對每一家都是 N/A，而一份真的沒揭露某列的財報是真實結果），所以這個檢查必須越過正常變異，只在整批失敗時才響。

它在 `fin_report_rows` 與 `statements` 的 CLI 兩個地方都印，而不是放在 `print_summary_rows` 裡——因為 `--export` 的兩條路徑都直接 return，從不印列，而批次執行正是整份讀壞最不容易被發現的地方。

已知的粗糙處：這是一個對所有列的平坦比例。真的太吵的話，修法是在 `SUMMARY_LAYOUT` 加一個逐列的「預期就是 N/A」旗標（活存比是已知案例），不是去調那個常數——常數不管設成多少都分不出兩種 N/A。

## 「判不出來就拒絕」在這個 codebase 的實作

同一條規則在五個地方各自長成不同樣子：

| 判不出什麼 | 做法 |
|---|---|
| 唯一機構 | `detect_bank` 回 None，要求 `--bank`（見[為什麼歧義要拒絕](entity-resolution.md#為什麼歧義要拒絕而不是取第一個)） |
| 產業的 layout | `collect_summary_rows` 丟 ValueError，要求 `--industry` |
| 表格的方向 | `detect_orientation` 回 None，跳過整張表 |
| 標題退路指的是哪一欄 | 要求剩下**恰好一欄**候選值欄，否則不比對 |
| 金管會的正式名稱 | 不猜，`gov_name_note` 說明為什麼 |

最後那條「恰好一欄」值得展開。用投影片標題當退路（表格自己的列／欄標籤太通用，但 `## 外幣放款` 這種區段標題點出了主題）在只有一欄候選時是安全的；有兩欄以上時標題告訴你主題卻沒告訴你是哪一欄，猜下去就是富邦 `企業授信餘額（依幣別）`（台幣授信 | 外幣授信）靜默回傳一半金額的路徑。

列方向那一側同理：如果剩下好幾個彼此無關的明細列（例如一張泛用的「各類放款佔比」，標題只在附註裡順帶提到那個詞），挑「第一個」是猜不是比對——中信金簡報實測，這裡曾經替一個根本沒有自己列的詞（信用卡循環）抓到一列無關的企業放款。
