# 業務領域

> 給不熟台灣金融申報制度的人／agent。理解這些之後，程式碼裡很多「奇怪的」判斷會變得顯然。

---

## 1. 兩種來源文件，兩種比對哲學

| | 財報（fin_report） | 法說會（con_call） |
|---|---|---|
| 是什麼 | 依主管機關準則編製的法定財務報告 | 給投資人的簡報，行銷性質 |
| 有無法規約束 | **有** | **無** |
| 有無科目代碼 | **有**，主管機關規定要印 | 沒有 |
| 格式一致性 | 高（同準則內） | 低（各家自由發揮，同一家逐季也會變） |
| 擷取策略 | **代碼精確比對** | **文字比對＋加權** |
| 設定住哪 | 程式碼（`SUMMARY_LAYOUT`、`BANK_PROFILES`） | **外部設定檔** `data/con_call_terms.json` |

**這個對照是整個專案最重要的一件事。** 兩邊策略相反不是不一致，是刻意的：法規產物用代碼、自由格式用可設定的詞彙表。

問「為什麼不統一」的時候，答案是：法說會詞彙由業務方擁有且頻繁變動，所以在設定檔裡；財報代碼由主管機關定義且穩定，所以在程式碼裡受測試保護。

## 2. 第三種文件：季報摘要揭露（finsum）

依「公開發行銀行財務報告編製準則」第三十二條，銀行要在網站揭露季度財務業務資訊。這是一份**比完整個體財報短得多**的文件（約 10–15 頁 vs 150–280 頁），但表格形狀與代碼慣例相同。

唯一實測到的差異是**稅後淨利的代碼會因銀行而異**，所以有獨立的 `code_overrides_finsum`。其餘完全共用 `collect_summary_rows`。

`cli` 用「含活期性存款比率 ＋ 檔案數 ≤30」判斷這個類型。

## 3. 科目代碼與產業字典

台灣的財務報告編製準則**按產業分立**：

| 準則 | 對應字典 |
|---|---|
| 金融控股公司財務報告編製準則 | `data/金控業.xlsx` |
| 公開發行銀行財務報告編製準則 | `data/金融業.xlsx` |
| 保險業財務報告編製準則 | `data/保險業.xlsx` |
| 證券商財務報告編製準則 | **沒有** |
| 票券金融公司財務報告編製準則 | **沒有** |

每本字典有四張表：資產負債表、綜合損益表、權益變動表、現金流量表；每張表同時含「原始」與「修正後」代碼區塊，**修正後優先**。

**同一個代碼在不同準則下意義不同。** 已實測確認的例子：`58200` 在金融業是呆帳提存（收回），在保險業是保險成本線。這就是為什麼產業判定不能省略、以及為什麼沒有 layout 的產業要拒絕而非套用預設。

### 常用代碼速查

| 代碼 | 意義 |
|---|---|
| `10000` | 資產總計 |
| `20000` | 負債合計 |
| `30000` | 權益總計 |
| `49010` | 利息淨收益 |
| `49100` | 手續費淨收益 |
| `58200` | 呆帳提存（收回）**←金融業限定** |
| `58400` | 營業費用 |
| `61001` | 稅前淨利 |
| `64000` / `63000` | 稅後淨利（範圍不同，見機構覆寫） |

`4xxxx` 是個特例 —— 它不是真代碼，是淨收益的槽位標記，實際靠 `SUMMARY_LABEL_FALLBACKS` 的標籤比對取值。

## 4. 代碼不可靠的地方，以及退路

有些小計／合計列的**代碼**不可靠，但**標籤文字**可靠：

- 實測某中信個體財報：小計列的首格代碼**根本是空的**
- 實測某國泰個體財報：「本期淨利」在 `61000`，不是覆寫假設的 `63000`/`64000`

`SUMMARY_LABEL_FALLBACKS` 處理這個。**它按代碼槽位鍵入，不按機構鍵入** —— 四家共用同一組措辭。這是刻意的設計取向：遇到差異時問「這是不是一類可共用的措辭」，而不是「這家要加什麼規則」。前者條目數收斂，後者發散。

## 5. 期間（period）為什麼用位置而非日期

`--period 1` 是最新一期、`2` 是次新，依文件由左至右的**排列位置**，不是解析日期標籤。

原因是這些財報一律把最近期放最左，而日期標籤的寫法（民國/西元、年月日/年季）在各家與各季之間不一致。位置是比日期字串更穩定的訊號。

**法說會相反** —— 簡報常把最舊期放最左。`decks` 有自己的期間排序邏輯（`_rank_periods`）。

## 6. 民國年

財報用民國年（ROC），`114年` = 2025 年。轉換散在 `derive_quarter_num`、`_normalize_year`、`disclosures` 的檔名解析裡。看到 `114`、`113` 這種數字時要意識到它是民國年。

## 7. 目前追蹤的機構

四家，全部是銀行／金控：

| 短名 | 別名（偵測用） | 法說會主體 |
|---|---|---|
| 國泰 | 國泰 | 國泰世華、Cathay United |
| 中信 | 中信、中國信託 | 中信銀、中國信託商業銀行、CTBC Bank |
| 北富銀 | 北富銀、台北富邦銀行、臺北富邦、富邦… | 台北富邦、Taipei Fubon |
| 玉山 | 玉山 | 玉山銀、E.SUN、ESUN |

「臺」與「台」都要列，兩種寫法都會出現在財報裡。

**別名必須是短名**，因為法說會封面只寫「玉山金控」不寫登記名稱。短名在集團內互為子字串，所以機構解析靠 `industries` 欄位收斂 —— 詳見 [ARCHITECTURE.md §1.2](ARCHITECTURE.md)。

### 目標範圍

長期目標是**金融業所有實體**（約 95 家：約 14 金控＋約 38 本國銀行＋約 40 家壽險產險），未來可能跨到其他產業。

明確**不含**：農漁會信用部（約 300 家，不同申報體系）、信用合作社、外國銀行在台分行。證券商與票券金融公司**待決**。

## 8. 為什麼揭露的 ROA/ROE 不能盲目年化

實測比對三家銀行各兩期後確認：**年化慣例各家不一致**。

- 中信、玉山的 Q1 揭露率與其 Q4 率量級相近（已年化）
- 國泰的 Q1 率約為 Q4 的 1/4（尚未年化）

所以揭露值**照原樣呈現**，不再乘 4/quarter_num，另外並列一個獨立的手算交叉檢查值。盲目縮放對其中至少一家一定是錯的。

## 9. 單位

財報金額一律以**新台幣仟元**表達，內部就用這個單位；只在匯出邊界（Excel）除以 1000 轉成百萬元。

法說會簡報單位不統一（拾億元、百萬元…），`decks` 有自己的單位偵測 `detect_unit_scale`，**在表格層級解析**。這是為什麼「全形括號負數」那類修正只能改解析、不能在單格上乘倍率 —— 會變成 1000 倍的錯。
